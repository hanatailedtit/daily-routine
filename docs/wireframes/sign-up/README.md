현재 프로젝트의 Google 인증, 프로필 데이터와 프로필 수정 UI를 기준으로 작성한 **무채색 와이어프레임 제안**입니다. 기존 로그인 방식은 Google만 사용합니다. SVG 제작 이후 [컬러 디자인](../../designs/sign-up/README.md)을 실제 앱에 적용했습니다. 원본 SVG는 유지했으며 예시 이메일은 가상의 데이터입니다.

## 설계 당시 코드에서 확인한 동작

- [Google 인증](../../../src/supabase/auth.ts): Google OAuth 완료 후 `/todo-page`로 돌아옵니다.
- [회원 정보 조회](../../../src/recoil/user/user-selectors.ts): 인증된 사용자의 `profiles` 행이 없으면 이메일을 이름으로, Google 사진을 이미지로 자동 저장합니다. 따라서 현재 앱에는 이 가입 화면으로 가는 단계가 없습니다. 조회 오류도 `null`로 반환합니다.
- [프로필 저장](../../../src/repository/user/profile.repository.ts): `id`, `user_name`, `user_image`를 저장할 수 있습니다. `id`는 인증 사용자의 ID이며 사용자가 입력하지 않습니다.
- [프로필 타입](../../../src/model/user/user-profile.dto.ts): 별도의 이메일·비밀번호·전화번호 필드가 없습니다.
- [프로필 수정](../../../src/pages/my-page/MyPage.tsx): 이름의 앞뒤 공백을 제거하고 빈 값을 거부하며, 입력 길이는 최대 60자입니다. 사진은 5MB 이하의 PNG·JPG·WebP·GIF를 허용합니다. 이 규칙을 가입 폼에도 적용하는 제안입니다.
- [라우터](../../../src/router/index.tsx): 현재 `/sign-up` 경로는 없습니다.

## 제안 흐름

`Google 인증 완료 → 회원 정보 조회 → 기존 회원은 할 일 / 신규 회원은 회원가입 → 저장 성공 → 할 일`

**정상 조회 결과가 없을 때만** 신규 회원으로 판단합니다. 인증 실패, 세션 만료, 회원 정보 조회 실패를 신규 회원으로 취급하지 않습니다. 조회 실패 화면에서는 재시도와 로그아웃을 제공합니다.

가입 화면은 작업용 사이드바나 할 일 메뉴 없이 표시합니다. 입력 중인 계정이 맞는지 확인할 수 있도록 Google 이메일을 읽기 전용으로 보여 줍니다. 이메일을 다시 입력하거나 추가 Google 인증을 진행하지 않습니다.

| 항목 | 구성 | 코드와의 연결 |
| --- | --- | --- |
| Google 계정 | 인증된 이메일, 읽기 전용 | `session.user.email`; `profiles` 저장 항목 아님 |
| 프로필 사진 | 선택 입력, Google 사진 또는 기본 이미지 | `user_metadata.avatar_url` → `user_image` |
| 닉네임 | 필수, 앞뒤 공백 제거 후 1~60자 | `user_name` |
| 가입 완료하고 시작하기 | 유효성 확인 → 저장 → 프로필 갱신 → `/todo-page` | `insertUserProfile` 재사용 |
| 로그아웃 | 세션 종료 후 로그인 화면 | `singOutForSite` 재사용 |

사진을 따로 선택하지 않아도 가입할 수 있습니다. 닉네임과 사진은 기존 ‘나의 기록’에서 변경할 수 있습니다. 이메일·비밀번호 회원가입, 이름 중복 확인, 새 개인정보 항목이나 동의 항목은 추가하지 않습니다.

## 배치와 상태

- 데스크톱: 왼쪽에 현재 단계를, 오른쪽에 480px 너비의 폼을 둡니다. Google 인증은 완료된 단계로 표시합니다.
- 모바일: 24px 여백 안에 같은 폼을 한 열로 배치합니다. 주요 입력·버튼은 56px, 사진 선택·로그아웃은 44px 이상의 높이를 확보합니다. 좁은 화면에서는 가로 여백을 16px로 줄이고 긴 이메일은 줄바꿈합니다.
- 모바일 제출 버튼은 본문 흐름에 둡니다. 키보드가 열리면 스크롤로 입력란과 제출 버튼에 접근하고, 하단 안전 영역을 확보합니다. 고정 버튼이 입력란을 가리지 않도록 합니다.
- 입력 오류: 필드 아래에 설명을 표시합니다. 포커스가 필드를 떠나거나 제출할 때 검사하고, 제출 오류 시 해당 필드로 포커스를 이동합니다. 빈 이름은 ‘닉네임을 입력해 주세요.’로 안내합니다.
- 사진 오류: 파일을 적용하기 전에 형식과 크기를 확인하고 사진 선택 영역 옆에 안내합니다. 이전 사진·입력값을 보존합니다.
- 가입 중: 버튼에 ‘가입하는 중…’과 진행 표시를 보여 주고 중복 제출을 막습니다. 버튼과 입력의 비활성 상태를 보조 기술에도 전달합니다.
- 저장 실패: 폼 안에 오류와 ‘다시 시도’를 표시하며 닉네임과 사진을 보존합니다. 저장 성공을 확인하기 전에는 할 일 화면으로 이동하지 않습니다.
- 저장 응답이 불확실하거나 이미 프로필이 생성되어 있다면 기존 행을 다시 조회합니다. 가입 재시도로 기존 이름·사진을 덮어쓰지 않습니다.

## 실제 앱 연결

이후 구현에서 `userProfileSelector`의 자동 생성을 제거하고 정상적인 빈 결과와 조회 오류를 구분했습니다. 인증된 신규 회원은 `/sign-up`으로 이동하며, 기존 회원이 직접 접근하면 할 일로 이동합니다. 인증되지 않은 사용자는 Google 로그인 화면으로 돌아갑니다.

가입 폼은 닉네임 검증·선택적 사진·저장 중 중복 제출 방지·오류 재시도를 제공합니다. 저장 전에 기존 행을 확인하고 응답이 불확실한 경우에도 다시 조회해 기존 프로필을 덮어쓰지 않습니다. 프로필 저장 권한은 인증 사용자 본인의 ID에 한정하는 기존 RLS 정책을 사용합니다.

## ui-ux-pro-max 적용과 검수

스킬의 디자인 시스템 검색은 Flat Design과 간결한 가입 흐름을 제안했으나, 함께 반환된 제품 데모·마케팅 패턴은 이 화면에 맞지 않아 적용하지 않았습니다. 좁힌 `onboarding form` UX 검색에서 적합한 제출 피드백·입력 라벨 규칙을 확인했습니다. 특정 가입 템플릿 일치는 확인하지 못했으므로, 화면 구조와 무채색 표현은 기존 프로젝트 와이어프레임을 기준으로 직접 구성했습니다.

추가 검색의 **Redundant Entry**, **Inline Validation**, **Focusable Error Summary** 중 이 폼에 필요한 계정 재입력 방지, 필드 근처 오류와 제출 시 포커스 이동을 반영했습니다. 필수 입력이 하나이므로 별도의 오류 요약 목록은 두지 않습니다.

SVG XML 구문·크기와 렌더링 이미지를 확인했습니다. 이후 실제 폼은 로컬 테스트 서버에서 인증 리다이렉트·회원 정보 분기·저장·재시도와 모바일 배치를 검증했습니다. 실제 Google/Supabase 계정, 스크린리더와 기기 키보드는 별도 확인이 필요합니다.
