# Daily Routine · 데스크톱 UI 디자인

기존 [와이어프레임 전체 보드](../../wireframes/desktop/desktop-wireframes.svg)에 시각 디자인을 적용했습니다. Google 로그인만 제공하는 흐름, 카테고리, 2단계 할 일, 서식 에디터, 프로필과 통계를 유지했습니다. 원본 와이어프레임과 앱 코드는 수정하지 않았습니다.

개별 화면은 **1440 × 1000**, 전체 보드는 **3088 × 2376**입니다. SVG는 브라우저로 열거나 Figma로 가져올 수 있습니다. 텍스트·도형을 벡터 요소로 유지했고 Google 로고만 프로젝트의 기존 PNG를 포함했습니다. 외부 이미지·폰트 요청, 스크립트, `foreignObject`는 없습니다.

## 디자인 방향

개인 할 일을 정리하는 사람이 다음 행동을 쉽게 찾는 화면이 목적입니다. 목록은 넓게, 편집은 옆에, 기록은 따로 배치한 기존 구조를 유지했습니다.

`use-design-md`로 [토스 카탈로그 DESIGN.md](https://www.getdesign.kr/services/toss/llms.txt)를 전체 확인하고 Known Gaps, Do's and Don'ts를 먼저 반영했습니다. 브랜드 미지정에 따라 안내한 기본안을 사용했습니다. 원본 문서의 출처와 이 프로젝트에서 보완한 판단은 아래에 구분했습니다.

`frontend-design`으로 단순히 무채색을 파란색으로 바꾸는 안을 검토한 뒤, 로그인 화면에 **실제 예시 8개 중 완료 3개를 나타내는 8칸 진행 표시와 일부 할 일 목록**을 적용했습니다. 습관 연속 기록을 새로 가정하지 않고, 현재 데이터의 ‘작은 완료가 쌓임’을 제품의 시각적 특징으로 삼았습니다. 나머지 화면에서는 이 요소를 반복 장식하지 않고 목록과 편집에 집중했습니다.

```text
로그인     [소개 + 예시 할 일]       [Google로 계속하기]
목록       [공통 사이드바]          [요약 / 2단계 할 일 목록]
편집       [공통 사이드바]          [카테고리 목록 | 서식 에디터]
마이페이지 [공통 사이드바]          [프로필 / 요약 / 통계]
```

## 색상

| 역할 | 값 | 근거와 적용 |
| --- | --- | --- |
| 기본 텍스트 | `#191F28` | 카탈로그 grey-900에 병기된 발행값. 제목과 본문 강조 |
| 보조 텍스트 | `#4E5968` | grey-700 발행값. 설명, 라벨 |
| 약한 텍스트 | `#6B7684` | grey-600 발행값. 흰 표면의 보조 정보 |
| 상태 강조 | `#3182F6` | blue-500 발행값. 완료 체크, 차트와 진행 표시 |
| 행동·선택 텍스트 | `#1065CC` | 카탈로그의 번들 고유 blue-600 `oklch(0.522 0.176 257)`를 sRGB로 근사 변환. 일반 글자 대비를 위해 이 역할로 사용한 것은 프로젝트 판단이며, TDS 발행 blue600과 동일하다는 뜻이 아님 |
| 약한 강조 표면 | `#E8F3FF` | blue-50 발행값. 선택 내비게이션, 로그인 소개 패널 |
| 배경·보조 버튼 | `#F2F4F6` | grey-100 발행값 |
| 보조 영역 | `#F9FAFB` | grey-50 발행값 |
| 표면 | `#FFFFFF` | white. 카드, 에디터, Google 버튼 |
| 구분선 | `#E5E8EB` | grey-200 발행값 |

카탈로그의 OKLCH는 원칙적으로 유지하되, 이번 산출물은 macOS Quick Look과 SVG 편집기 간 호환성을 위해 문서에 병기된 hex를 사용했습니다. hex가 병기되지 않은 blue-600은 수학적으로 변환한 **sRGB 근사값**입니다. 카탈로그의 반올림된 OKLCH와 hex가 완전히 같다고 가정하지 않습니다.

원색 블루 위 흰색 17px 버튼 글자는 대비가 부족하므로, 주요 버튼에는 어두운 블루를 적용했습니다. 주요 행동은 목록의 ‘할 일 추가’, 편집의 ‘변경 저장’으로 각각 하나입니다. Google 버튼은 기존 Google 로고를 유지한 흰색 버튼이며 별도 파란색 로그인 버튼을 추가하지 않았습니다. 미완료 통계는 패턴·범례·개수로도 구분합니다.

## 서체·간격·컴포넌트

- **표시·제목:** Pretendard 700, 로그인 56/40px, 화면 제목 28px, 패널 제목 24px, 목록·차트 제목 20px. 큰 제목은 -2% 자간을 적용했습니다.
- **본문:** Pretendard 15px, 할 일 제목은 17px로 한 단계 강조했습니다. 설명은 13px입니다. 각 줄의 간격을 명시적으로 배치했습니다.
- **제품 워드마크:** Avenir Next 700을 절제해서 사용했습니다. 이는 프로젝트의 추가 판단이며 카탈로그 지정 서체가 아닙니다.
- **폰트 제약:** Toss Product Sans는 재배포하지 않았습니다. 카탈로그가 지정한 대체 서체 Pretendard를 사용했습니다. 폰트는 SVG에 내장하지 않아, 수신 환경에 Pretendard가 없으면 Apple SD Gothic Neo 등의 대체 글꼴이 사용됩니다. 편집 시 같은 글꼴을 설치하면 폭이 더 안정적입니다.
- **공통 프레임:** 240px 사이드바, 48px 본문 좌우 여백, 24px 카드 내부 여백. 데스크톱 배치는 기존 와이어프레임과 프로젝트의 판단이며 토스의 공식 데스크톱 규격이 아닙니다.
- **모서리:** 카드 24px, 로그인 소개 패널 32px, L 버튼 48px 높이/14px 반경, M 버튼 40px 높이/12px 반경, Google 버튼 56px 높이/16px 반경. 카탈로그의 크기별 반경을 사용했습니다.
- **아이콘·체크:** 24px 격자 기반의 단순 아웃라인을 `currentColor`로 그렸습니다. 체크박스는 22px/6px 반경이며 하위 항목만 기존 정보 밀도에 맞춰 20px로 조정했습니다. 공식 아이콘 파일을 사용한 것은 아닙니다.
- **표면:** 그림자, 그라디언트, 노이즈, 컬러 좌측 장식선을 추가하지 않았습니다. 차트 축선도 제거했습니다. 카탈로그의 평면 표면과 단일 강조색 규칙을 따랐습니다.
- **카피:** 기능명과 버튼을 유지하면서 문장형 설명은 해요체로 정리했습니다. 원본 브랜드명·시스템명은 제품 화면에 표시하지 않았습니다.

## 검수와 범위

네 개의 SVG와 전체 보드를 XML 파싱했고, 중복 ID·외부 요청·스크립트 유무를 검사했습니다. 원본 와이어프레임의 SHA-256이 작업 전후 동일한지 확인했습니다. Google 외 로그인 UI가 없고, 예시 데이터가 전체 8개/완료 3개/미완료 5개/완료율 37.5%로 일치하는지 확인했습니다.

macOS Quick Look으로 렌더링하여 네 화면의 글자·컨트롤·차트 배치를 시각적으로 확인했습니다. 주요 텍스트 조합의 대비는 4.5:1 이상이며, 흰 버튼 글자/행동 블루는 약 5.59:1, 보조 텍스트/흰색은 약 7.11:1, 선택 텍스트/약한 블루 표면은 약 4.98:1입니다. 체크박스 등 상태 그래픽은 일반 글자와 구분했습니다.

생성일별 통계는 `created_at`으로 묶은 **현재 완료 상태**입니다. 완료일·연속 달성 기록을 의미하지 않습니다. 로그인 소개의 수치와 목록도 예시입니다.

정적 데스크톱 디자인 산출물입니다. 앱 구현, 실제 OAuth/API, 모바일·다크 모드, 키보드·스크린리더·동작 상태 검증은 포함하지 않았습니다. 원본 와이어프레임 README에 남아 있는 skeleton 권고와 달리, 이 디자인을 구현할 때의 로딩은 선택한 문서에 따라 shimmer 없는 3-dot 표시를 기준으로 합니다.
