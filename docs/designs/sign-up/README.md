승인된 회원가입 와이어프레임에 기존 [데스크톱](../desktop/README.md)·[모바일](../mobile/README.md) 디자인을 이어 적용했습니다. Google 인증 계정 안내, 필수 닉네임, 선택적 사진, 가입 완료와 로그아웃을 유지했습니다. SVG 제작 이후 이 디자인을 실제 `/sign-up` 화면에 반영했습니다. 원본 SVG는 유지했습니다.

## 적용 방향

`use-design-md`의 [토스 카탈로그 DESIGN.md](https://www.getdesign.kr/services/toss/llms.txt)를 앞선 작업에서 전체 확인한 캐시를 기준으로 사용했습니다. Known Gaps와 Do's and Don'ts를 다시 확인했으며, 별도의 브랜드나 팔레트를 도입하지 않았습니다. 출처 문서의 이름은 제품 UI에 표시하지 않습니다.

`frontend-design`에서는 **Google 연결 완료 → 회원 정보 입력**이라는 실제 과정에 강조를 집중했습니다. 데스크톱의 옅은 블루 패널 안에서 완료 체크와 현재 단계가 이어집니다. 모바일은 같은 정보를 짧은 계정 안내와 한 열 폼으로 전달합니다. 장식용 수치·일러스트·추가 기능은 넣지 않았습니다. 질문형 소개 문구는 ‘나만의 루틴을 시작할 준비가 됐어요.’로 정리했습니다.

```text
데스크톱 [소개 + 인증 완료/현재 단계] [Google 계정 / 사진 / 닉네임 / 가입 완료]
모바일   [Google 계정 → 사진 → 닉네임 → 가입 완료]
상태     [입력 오류] [가입 중] [저장 실패와 다시 시도]
```

## 색상과 서체

| 역할 | 값 | 적용 근거 |
| --- | --- | --- |
| 제목·기본 텍스트 | `#191F28` | 기존 제품의 grey-900 |
| 설명·플레이스홀더 | `#4E5968` | grey-700; 옅은 배경에서도 읽을 수 있도록 유지 |
| 주요 행동·현재 단계 | `#1065CC` | 기존 제품의 대비 보정 블루 |
| 완료 체크 | `#3182F6` | 기존 완료 상태 색상 |
| 소개·아바타 표면 | `#E8F3FF` | 기존 약한 강조 표면 |
| 배경·입력·보조 버튼 | `#F2F4F6` | 기존 배경 색상 |
| 카드 | `#FFFFFF` | 흰 표면 |
| 구분선 | `#E5E8EB` | 기존 구분선 |
| 입력 경계 | `#6B7684` | 경계의 3:1 대비를 확보하기 위한 프로젝트 판단 |
| 오류 텍스트·아이콘 | `#C7293B` | 현재 Tailwind의 destructive 값 재사용; 카탈로그의 공식 red-500을 뜻하지 않음 |
| 오류 입력 경계 | `#F04452` | 카탈로그 red-500의 병기된 hex |

`#1065CC`는 이전 디자인에서 선택한 카탈로그 번들 고유 blue-600의 sRGB 근사값입니다. TDS 발행 blue600과 동일한 값이라고 주장하지 않습니다. SVG 편집기와 Quick Look 호환성을 위해 기존 산출물과 동일하게 hex를 사용했습니다. 상세 출처와 변환 근거는 [기존 디자인 설명](../desktop/README.md)에 있습니다.

제목·본문은 Pretendard, 제품 워드마크는 기존 디자인의 Avenir Next 스택을 사용합니다. 소개 제목은 40px, 화면 제목은 28px, 본문·라벨은 16px, 주요 버튼은 17px, 보조 정보는 13/14px입니다. Toss Product Sans는 재배포하지 않았습니다. 서체는 SVG에 내장하지 않아, 설치되지 않은 환경에서는 대체 글꼴이 사용됩니다.

## 컴포넌트와 상태

- 카드 반경 24px, 소개 패널 32px, 주요 버튼 56px/16px 반경을 사용합니다. 그림자와 그라디언트는 없습니다.
- 사진 선택·로그아웃의 44px 높이, 56px 입력란, 입력란의 14px 반경은 승인된 와이어프레임과 모바일 터치를 위한 프로젝트 선택입니다. 카탈로그의 공식 입력 규격은 48px/12px입니다.
- 주요 행동은 ‘가입 완료하고 시작하기’ 하나로 강조하고 보조 행동은 회색으로 구분합니다. 오류 상태의 빨강은 의미 전달용 색상입니다.
- 입력 오류는 1.5px 빨간 경계와 필드 아래 아이콘·문구를 함께 표시합니다. 색상만으로 구분하지 않습니다.
- 가입 중에는 버튼 안에 점 세 개와 ‘가입하는 중…’을 표시합니다. 애니메이션은 SVG에 포함하지 않습니다. 실제 구현에서는 중복 제출을 막고 진행 상태를 보조 기술에도 전달해야 합니다.
- 저장 실패에는 오류 안내와 ‘다시 시도’를 배치합니다. 닉네임과 사진 보존, 조회 실패와 신규 회원 구분은 원본 설계를 유지합니다.
- 모바일 버튼은 본문 흐름에 둡니다. 키보드가 열렸을 때의 스크롤과 하단 안전 영역은 구현 시 처리합니다.

## 검수와 범위

세 SVG를 XML로 검사하고 개별 화면과 전체 보드를 PNG로 렌더링해 확인했습니다. 중복 ID, 외부 이미지·폰트 요청, 스크립트와 `foreignObject`는 없습니다. 텍스트와 도형을 편집 가능한 벡터로 유지했습니다.

주요 대비는 흰 버튼 글자/행동 블루 **5.59:1**, 보조 텍스트/흰색 **7.11:1**, 보조 텍스트/회색 입력 **6.45:1**, 행동 블루/옅은 블루 **4.98:1**, 오류 텍스트/흰색 **5.51:1**입니다. 입력 경계와 오류 경계는 인접 표면 대비 3:1 이상입니다.

SVG 자체는 정적 산출물이며 다크 모드와 다른 화면 폭의 개별 시안은 포함하지 않았습니다. 이후 앱에서는 자동 프로필 생성을 제거하고 신규 회원 분기·닉네임과 사진 저장·오류 재시도·중복 생성 방지를 구현했습니다. 로컬 테스트 서버로 Google 리다이렉트와 가입 흐름을 검증하며, 실제 Google/Supabase 계정 연결은 별도 확인이 필요합니다. 원래 연결 제안과 검증 규칙은 [와이어프레임 문서](../../wireframes/sign-up/README.md)에 정리했습니다.
