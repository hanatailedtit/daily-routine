# 프로젝트 코드 리뷰 · 2026-10-29

React 18, Recoil, React Router 6, Supabase 데이터 계층, 편집기, 공통 UI, 인증, SQL 초기화, 빌드 설정과 테스트를 점검했다. 작업 시작 시 Git 작업 폴더와 스테이징은 깨끗했다. DB 스키마·RLS·원격 데이터는 변경하지 않았으며 커밋·푸시·배포도 수행하지 않았다.

## Tiptap 교체와 동작 보존

- 기존 `todo_text` HTML 컬럼과 data URL 이미지 저장을 유지한다. DB 변환이나 데이터 일괄 재저장은 없다.
- 제목·본문·굵게·기울임·밑줄·목록·인용·코드 블록·링크·이미지·표·실행 취소·다시 실행·HTML 소스 편집을 제공한다.
- UI는 기존 shadcn/ui와 Tailwind를 사용한다. 저장 실패 시 작성 내용 유지, 중첩 링크 팝업, 키보드 포커스, Esc·바깥 클릭·뒤로 가기의 미저장 확인, 모바일 전체 화면 동작을 유지한다.
- Tiptap은 지원하는 스키마로 HTML을 정규화한다. 기존 데이터의 기본 서식·이미지·표를 검증했지만 임의의 HTML·인라인 스타일까지 완전히 동일하게 유지한다고 보장하지 않는다.
- Google 인증·신규 회원 프로필 등록·기존 회원 진입·카테고리 선택·완료 연동·정렬·삭제 동작은 기존 브라우저 테스트로 확인한다.

구현 참고: [Tiptap React 설치](https://tiptap.dev/docs/editor/getting-started/install/react), [이미지](https://tiptap.dev/docs/editor/extensions/nodes/image), [표](https://tiptap.dev/docs/editor/extensions/nodes/table).

## 남은 위험과 보류 범위

- 여러 행의 저장·정렬·삭제는 여전히 별도 REST 요청이다. 실패 후 상태는 복구 조회하지만 DB 트랜잭션처럼 전체 성공/전체 롤백을 보장하지 않는다. 원자성이 필요하면 별도 DB 함수/RPC 설계·마이그레이션이 필요하다.
- 대량 데이터 조회는 offset 페이지 방식이다. 다른 클라이언트가 조회 도중 목록을 바꾸면 일관된 DB 스냅샷을 보장하지 않는다.
- Vite는 호환성을 유지하는 4.5.14로 갱신했지만, 새 메이저에서만 수정되는 보안 권고가 남는다. 개발 서버를 외부에 공개하는 조건 등 실제 적용 범위는 [공급자 권고](https://github.com/vitejs/vite/security/advisories/GHSA-4w7w-66w2-5vf9)를 참고한다.
- React Router 6에도 [신뢰하지 않는 경로의 외부 이동](https://github.com/remix-run/react-router/security/advisories/GHSA-wrjc-x8rr-h8h6)과 [SSR hydration](https://github.com/remix-run/react-router/security/advisories/GHSA-337j-9hxr-rhxg) 권고가 있다. 이 앱은 이동 경로를 내부 경로로 구성하며 SSR hydration은 사용하지 않는다. 권고의 버전 범위에는 해당하지만 이 앱에서 해당 공격 경로가 재현된 것은 아니다. 메이저 교체는 이번 변경에 포함하지 않았다.
- `yarn audit`은 일부 전이 의존성의 경고를 계속 반환한다. 경고 개수는 공격 가능성이 확인된 앱 취약점 개수와 같지 않다. 모든 경고가 해결됐다고 주장하지 않는다.
- 최종 감사 결과는 고유 권고 URL 108개이며 Yarn의 의존 경로별 집계는 low 49 / moderate 135 / high 178 / critical 28이다. `tinymce`, `dompurify`, `@tiptap/core`, `@tiptap/react`, `storybook` 자체의 권고는 최종 결과에 없지만 개발 도구의 전이 의존성 및 React Router 등의 경고는 남는다.
- 앱 빌드의 기존 sourcemap 위치 경고와 큰 청크 경고는 남는다. 이를 숨기기 위해 빌드·린트 설정이나 검사 규칙을 끄지 않았다.
